## 2. 任务与方法

### 2.1 任务范围

用户要求：阅读 KSP 本地化指南，汉化游戏中所有模组，完成后生成报告，并制作一个可上传 GitHub 的新模组。

因此工作分三部分：

1. 审计：找出所有模组中"有可本地化文本、但缺少中文"的部分；
2. 实现：以独立模组 + ModuleManager 补丁的方式补齐翻译；
3. 交付：打包、文档、报告、GitHub 发布结构。

### 2.2 指南要点

参考指南给出的核心方法：

- **原生词条**：模组若使用 `GameData/<Mod>/Localization/en-us.cfg` + `zh-cn.cfg`，只需提供 `zh-cn.cfg`，节点格式为：

  ```
  Localization
  {
      zh-cn
      {
          #tag = 文本
      }
  }
  ```

- **字面量字段**：`PART` 的 `title/description/manufacturer`、`VARIANT` 的 `displayName/description`、`AGENT`、`EXPERIMENT_DEFINITION`、`RESOURCE_DEFINITION`、`RDNode` 等写在 cfg 里的文本，用 ModuleManager 补丁改写，配合 `:NEEDS[模组]`、`:FINAL`、`:HAS[]`、正则 `^=` 等语法。
- **DLL 硬编码**：只能用 Harmony 在运行时替换 `Localizer.Format` / `GetStringByTag` 的返回值，本篇不涉及（原因见第 8 节）。
- **编码**：所有 cfg 必须为 UTF-8。
- **注意事项**：不要翻译被逻辑匹配的字段（如 Kerbalism 的 Configure `title`）；搜索关键词 `tags` 是否翻译需权衡。

## 4. 方案设计

### 4.1 总体结构

```
GameData/KSP-ZH-CN-Extended/
├── KSP-ZH-CN-Extended.version
├── Localization/
│   ├── zh-cn.cfg          # 全部中文词条
│   └── en-us.cfg          # 字面量字段的英文原文（供英文环境）
└── Patches/
    ├── UmbraSpaceIndustries.cfg
    ├── Interkosmos.cfg
    ├── ...
```

不修改任何原模组文件；所有补丁带 `:NEEDS[模组]` 与 `:FINAL`，仅在对应模组存在时生效。

### 4.2 原生标签：直接补 `zh-cn`

对已有 `en-us` 定义的标签，在 `Localization/zh-cn.cfg` 中补充同名 `#tag = 中文`。KSP 的本地化系统会按当前语言查找，缺失时回退英文。

### 4.3 字面量：标签间接

直接把 `title` 改成中文会带来两个问题：英文环境被强制中文、后续维护困难。因此采用"标签间接"：

1. 补丁把字段改为引用 `#LOC_KSPZH_<uid>`；
2. `en-us.cfg` 写英文原文；
3. `zh-cn.cfg` 写中文。

示例：

```
@PART[MKS_Drill_02A]:NEEDS[UmbraSpaceIndustries]:FINAL
{
    @title = #LOC_KSPZH_12
}
```

优点：切换语言正确显示；英文玩家不受影响；翻译与原文一一对应，便于校对。

### 4.4 变体（VARIANT）处理

KSP 的 `VARIANT` 节点嵌在 `MODULE`（`ModulePartVariants` 或 `ModuleCargoPart`）内部，而不是 `PART` 的直接子节点：

```
PART
{
    MODULE
    {
        name = ModulePartVariants
        VARIANT
        {
            name = Orange
            displayName = ...
        }
    }
}
```

因此补丁必须逐层定位：

```
@PART[KIS.Container8]:NEEDS[KIS]:FINAL
{
    @MODULE[ModulePartVariants]
    {
        @VARIANT[Orange]
        {
            @displayName = #LOC_KSPZH_300
        }
    }
}
```

实现上先扫描全部 cfg，记录 `PART → MODULE → VARIANT` 的真实层级，再生成补丁，避免把变体挂到错误的 MODULE 下。

### 4.5 实验节点

`EXPERIMENT_DEFINITION` 用 `id` 而非 `name` 定位：

```
@EXPERIMENT_DEFINITION[id=...]:NEEDS[Interkosmos]:FINAL
{
    @title = #LOC_KSPZH_...
}
```

审计时曾因只读 `name` 漏掉 13 条实验标题，已修正为同时读取 `name`/`id`。

### 4.6 名称转义

ModuleManager 的节点名中空格需写作 `?`；生成补丁时统一替换。译文中的 `//`、`{`、`}` 会被清理或转全角，避免破坏 cfg 结构。

## 5. 实施过程

1. **审计脚本**：遍历 5740 个 cfg，容错解析（去注释、跟踪花括号栈），统计标签定义与引用，输出缺口清单。
2. **清单生成**：合并"标签缺口"与"字面量缺口"，按文本去重分配 `uid`，分成 10 个批次（USI 标签 3 批、Interkosmos 2 批、USI 部件 3 批、VABOrganizer、杂项标签、杂项部件）。
3. **翻译**：10 个并行子代理按批次翻译，统一 KSP 术语表；要求保留 `<<1>>`、`<color>`、`\n`、`%s`、`{0}` 等占位符。
4. **校验**：检查 uid 覆盖、占位符一致性、空值、非中文残留、长度异常。
5. **人工修订**：修正 12 处术语/语序问题（如 `Photopolarimeter` 统一为"偏振光度计"、`Hydrometer` 统一为"湿度计"、`Experiment Value` 改为"实验数值"），并补译 24 条遗漏长文本。
6. **装配**：生成 `zh-cn.cfg`、`en-us.cfg` 与 12 个补丁文件；同一标签去重；清理旧补丁，避免失效引用。
7. **静态校验**：`work/verify.py` 检查括号、重复、空值、占位符、未定义引用。
8. **实测**：把生成物复制进游戏目录并启动 KSP，确认 cfg 层与 v1.1.1 的 DLL 插件均能随游戏加载（日志见第 7.1、7.2 节）；模组窗口未逐项点击验证。

### 7.1 运行时 DLL 界面汉化（v1.1.x 历史，v1.2.0 词库已重建为 2,359 条）

配置层只能覆盖 cfg 中的字段。各插件用 C# 写在程序集里的窗口、按钮、提示，需要运行时替换才能显示中文。v1.1.0 因此增加了一个独立 Harmony 插件与一份运行时词库：

- **翻译**：分 16 批交给子代理翻译，术语表、占位符与专名规则与配置层一致；最终 **1298 条**写入 `DllLocalization/zh-cn.txt`（其余 366 条为标识符、颜色码、品牌名，或 MechJeb2 自带中文的条目，保留原文且不收录）。
- **插件**：`Plugins/KSPZHCN.dll`（Harmony 2.2.1.0），注册 **77 个前缀补丁**，覆盖：
  - `GUI` / `GUILayout` 的 `Label`、`Box`、`Button`、`RepeatButton`、`TextField`、`TextArea`、`Toggle`、`BeginGroup`/`BeginArea`、`BeginHorizontal`/`BeginVertical`、`Window`/`ModalWindow`、`tooltip`；
  - `GUIContent` 构造函数、`text`/`tooltip` 属性与 `Temp`，`UnityEngine.UI.Text.text`；
  - `ScreenMessages.PostScreenMessage` 的全部字符串重载；
  - `DialogGUILabel`、`DialogGUIButton`、`MultiOptionDialog` 的文本参数。
- **校验**：`work/assemble_dll.py` 检查 uid 覆盖（1664/1664）、空值 0、冲突 0、占位符不一致 0；控制台 harness 验证词库解析与查找；实机 `KSP.log` 输出 `dictionary loaded: 1298 entries`、`harmony patches: ok=77 fail=0`，游戏进入主菜单且无异常。
- **开关与扩展**：`DllLocalization/disabled.txt` 可整体关闭插件；`zh-cn.txt` 为 `原文<TAB>译文` 纯文本，可直接追加词条，重启生效。

### 7.2 飞行界面卡顿事故与修复（v1.1.1）

用户反馈"现在在飞船界面运行非常卡顿"。检查 `KSP.log` 发现：

```
NullReferenceException
  System.Globalization.TextInfo.GetInvariantCaseInsensitiveHashCode (System.String str)
  System.Collections.Generic.Dictionary`2.TryGetValue (...)
  KSPZHCN.Translator.T (System.String s)
  KSPZHCN.Patches.P0 (System.String& __0)
  (wrapper dynamic-method) UnityEngine.GUI.Button_Patch1(UnityEngine.Rect,string)
  MuMech.MechJebModuleMenu.DrawGUI ...
```

- **根因**：v1.1.0 用 `Dictionary<string,string>(StringComparer.OrdinalIgnoreCase)` 做大小写无关查找。KSP 的 Mono 运行时对部分界面字符串（含非 ASCII 符号、特殊大小写字符等）在计算忽略大小写哈希时抛 `NullReferenceException`。该异常发生在 GUI 前缀里，等于每个控件每帧抛一次；日志记录本身又很昂贵，最终表现为飞行界面严重卡顿（`KSP.log` 中同类异常 1000+ 条）。
- **修复**：词库加载时额外建立一份全部小写的 `Dictionary<string,string>`（`StringComparer.Ordinal`），查找时只在字符串含大写字母时才做 `ToLowerInvariant()`；彻底移除 `OrdinalIgnoreCase` 与可变的共享缓存（词库加载后只读，天然线程安全）；`T()` 整体 try/catch 返回原文，`P0..P3` 前缀也各加 try/catch，保证任何异常都不会传给游戏。
- **复验**：重编译安装后启动，`KSP.log` 中 `[KSPZHCN] dictionary loaded: 1298 entries`、`harmony patches: ok=77 fail=0`，`KSPZHCN` 相关异常为 0。

### 7.3 v1.2.0 实机验证

## 8. 已知限制

1. **DLL 层词库基于启发式提取**：只收集 IL 中紧邻 GUI 调用点的字符串常量；运行时拼接、格式化或从配置文件读取的文本（如 `"Warp to " + x`）可能仍是英文，可在 `zh-cn.txt` 中手动补充。
2. **实机验证范围**：v1.2.0 已确认插件加载（2,359 条）、77 个补丁全部注册、ModuleManager 无本包相关错误；但未对所有模组的每个窗口逐项点击验证，个别窗口可能出现漏译或排版问题。首次安装后建议查看 `KSP.log` 中的 `[KSPZHCN]` 行；如需回退英文界面，在 `DllLocalization/` 放置 `disabled.txt` 即可。
3. **搜索关键词（tags）**：部分标签译文替换了英文关键词，中文搜索更友好，但可能影响英文关键词检索。这是有意权衡。
4. **版本漂移**：补丁按 2026-11 时安装的模组版本编写；模组更新后若部件改名，补丁可能失效（不会报错，只是不生效）。
5. **多汉化包共存**：与 `0000Tinygrox_CNPatches` 使用不同标签名，理论上不冲突；若其他汉化包也改写同名字段，加载顺序可能影响最终显示。
6. **未包含 CKAN 元数据**：如需上架 CKAN，需另行提交 netkan。

## 9. 安装与卸载

安装：

1. 安装 ModuleManager 4.x（配置层需要）与 Harmony 2.x（DLL 层需要；游戏内 `000_Harmony` 已提供）；
2. 把压缩包中的 `GameData` 合并到 KSP 根目录；
3. 游戏设置中选择 `简体中文 (zh-cn)`；
4. 进入 VAB/SPH 检查部件名称与描述；打开任意模组窗口检查 DLL 层译文，`KSP.log` 中应有 `[KSPZHCN]` 行。

卸载：删除 `GameData/KSP-ZH-CN-Extended/` 即可，不影响原模组。只想关闭 DLL 层时，在 `DllLocalization/` 放置空文件 `disabled.txt`。
